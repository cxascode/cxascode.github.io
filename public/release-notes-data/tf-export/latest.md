### Export behavior

- When `resource_filters` use the `resource_type::id` form, loading export metadata for a type can request only those IDs (including on later dependency-resolution passes) instead of listing every resource of that type in the org, for resource types whose exporter supports targeted ID lookup. Regex and label filters still list the full type and filter the result locally.
- IDs named in an ID filter that no longer exist in Genesys Cloud are skipped in the metadata map rather than reported as errors, matching the previous list-then-filter behavior.
- Targeted ID lookups run with bounded concurrency (up to ten IDs at a time), which can shorten large ID-filtered exports when targeted lookup is available.

### Related export output changes

- Instances the exporter emits as Terraform data sources (for example managed sites or default locations) now write generated configuration from a dedicated data-source attribute set. Previously the same in-memory state used during enumeration was overwritten with data-source fields before serialization, which could produce incorrect or incomplete `data` blocks on export. Re-running export may change `data` block content for those instances without changing your `genesyscloud_tf_export` arguments.

### Upgrade impact

- Existing `genesyscloud_tf_export` configurations are likely unaffected.
- ID-filtered exports may complete faster and with fewer list API calls when the filtered types support targeted ID enumeration; other filter modes behave as before.
- Re-export jobs that produce `data` blocks for non-managed entities may see corrected attribute values in generated `.tf` output.
