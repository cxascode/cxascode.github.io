### Export behavior

- When no resources match the export scope, the error message is now `No resources found to export` instead of `resources cannot be empty`.
- Resource-type enumeration during export sanitization is now limited to the provider `max_clients` setting, which can change export speed and API load for large exports.
- When sanitization fails for one resource type, remaining in-flight resource-type enumerations are cancelled instead of continuing.
- Export sanitization now respects parent request cancellation, so interrupted exports can stop in-flight resource enumeration sooner.

### Upgrade impact

Existing `genesyscloud_tf_export` configurations are likely unaffected because no resource attributes changed. Export sanitization may run with lower concurrency when provider `max_clients` is set below the number of resource types being exported. Sanitization failures may return sooner because other in-flight enumerations are cancelled. The only message change is when an export finds no matching resources.
