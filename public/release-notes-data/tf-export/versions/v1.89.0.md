### Export behavior

- Custom reference fields that resolve to Terraform data sources during sanitization now honor `replace_with_datasource`: a resolver only adds a `data` block and rewrites the attribute when the target data source type is listed in `replace_with_datasource`, unless that resolver is treated as an always-resolve case (still emits a data source reference even when the type is omitted from the list).
- Speech and text analytics topic GUIDs follow the same rule: they become `data.genesyscloud_speechandtextanalytics_topic` references only when `genesyscloud_speechandtextanalytics_topic` is included in `replace_with_datasource`; otherwise exported values stay as raw topic IDs.
- After `exclude_attributes` are applied, the export pass adds explicit dependencies so `genesyscloud_user` resources that share a DID with an IVR depend on that IVR, encouraging the IVR to be created first in generated configuration. Matching uses post-exclusion DNIS or address values, so attributes you exclude are not used for this linkage.

### Related export output changes

- Exported `genesyscloud_user` and IVR resources that share a DID may show new `depends_on` (or equivalent dependency) relationships compared with v1.88.0.
- Resources referencing speech and text analytics topics may export topic IDs as literals instead of data source references when `genesyscloud_speechandtextanalytics_topic` is not in `replace_with_datasource`.
- Other attributes handled by custom data-source resolvers may stop generating extra `data` blocks when their type was not listed in `replace_with_datasource`, unless the resolver is in the always-resolve category.

### Upgrade impact

Existing `genesyscloud_tf_export` argument blocks are likely unaffected; no new or removed resource attributes appear in this release. Re-running export may change generated HCL for topic references, optional data blocks, and user–IVR ordering when DIDs are shared. Review diffs before applying regenerated configuration, especially if you relied on data source blocks for types you did not list in `replace_with_datasource`.
