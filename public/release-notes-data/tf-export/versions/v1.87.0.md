### Export behavior

- With `export_computed = false`, nested blocks that are marked computed on the container but still contain user-settable child fields are no longer removed wholesale. Computed leaf fields inside those blocks are still excluded, but user-editable nested values are kept in exported configuration (for example, integration `config` blocks that mix computed metadata with user input).
- With `export_computed = false`, nested blocks that end up with only nil fields after sanitization are dropped from exported configuration instead of appearing as empty `block {}` shells. Blocks that retain at least one non-nil value—including intentionally preserved empty lists—are unchanged.
- With `export_computed = false`, when every direct child of a nested block is excluded as computed, the exporter omits the entire block path rather than emitting an empty nested block.
- Unresolvable optional reference attributes inside nested maps or list elements are now collected using the full attribute path. Generated unresolvable-reference names for nested attributes use path segments (dots converted to underscores) instead of only the leaf attribute name.
- When `include_state_file` is enabled, exported `terraform.tfstate` entries set each resource’s `meta.schema_version` from the provider schema version for that resource type instead of always writing `0`.

### Related export output changes

- Resources with computed container blocks that include user-settable nested fields (notably `genesyscloud_integration` `config`) export more complete nested configuration when `export_computed = false`.
- Exports that emit unresolvable-reference sidecar output for nested optional references may list additional attributes or use different generated variable names than in v1.86.2.
- Re-exported state files may show non-zero `schema_version` values in resource `meta` for types that use a migrated provider schema, which can affect plan behavior after importing or refreshing against that state.

### Upgrade impact

Existing `genesyscloud_tf_export` argument blocks are likely unchanged; no new or removed export resource attributes appear in this release. Default exports (`export_computed = true`) may differ slightly in nested unresolvable-reference reporting and in `terraform.tfstate` `schema_version` values when `include_state_file` is enabled. Teams that set `export_computed = false` should re-run exports and expect fewer empty nested blocks and more complete user-editable nested fields on affected resource types.
