### Runtime behavior changes

#### Plan behavior
- genesyscloud_business_rules_decision_table — Refresh no longer runs the consistency checker after read, avoiding read loops and plugin timeouts on large tables; Terraform’s normal plan diff still detects drift. Nested `defaults_to` values under row columns are always written with stable empty `value`, `special`, and `values` siblings so null versus empty string flapping does not cause perpetual diffs.
- genesyscloud_outbound_dnclist — For RDS-type lists, `entries` are fetched and reconciled in state only when your configuration declares a non-empty `entries` block; omitting `entries` leaves state unchanged and avoids phantom plan diffs and expensive full-list reads on refresh.
- genesyscloud_routing_queue — Plan validates that when `all_outbound_email_addresses` is set, `outbound_email_address` is set and appears in that list (when queue-managed outbound email is in use). On refresh, list order is preserved when the set of domain/route pairs matches the API, avoiding order-only perpetual diffs.
- genesyscloud_speechandtextanalytics_dictionaryfeedback — Refresh keeps existing `example_phrases` in state when the API returns none (common for English/Spanish dialects), instead of clearing them and forcing a perpetual diff.

#### Apply behavior
- genesyscloud_organization_authentication_settings — Create and update send `universal_logout` to the organization authentication settings API.
- genesyscloud_routing_queue — Create and update include `all_outbound_email_addresses` in queue email media settings when configured.
- genesyscloud_routing_skill — Create assigns `division_id` on the initial create request instead of creating the skill and then moving it with a separate update.
- genesyscloud_speechandtextanalytics_dictionaryfeedback — After delete, the provider waits up to 10 minutes (previously 3 minutes) for the API to return not found before treating deletion as complete.

#### Export behavior
- genesyscloud_routing_queue — Export resolves references for `all_outbound_email_addresses.domain_id` and `all_outbound_email_addresses.route_id`, and omits list entries missing `route_id` from export output like other outbound email blocks.
